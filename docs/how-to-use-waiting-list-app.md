# 이용인 대기자관리 앱 실제 사용 방법

이 문서는 현재 저장소의 React/Vite 앱을 실제로 실행하고, 현장에서 테스트하고, Google Apps Script/Google Sheets 환경에 반영할 때 필요한 절차를 정리합니다.

## 1. 현재 코드가 하는 일

현재 앱은 브라우저에서 실행되는 대기자관리 화면입니다. 다음 기능을 제공합니다.

- 대시보드 통계 확인
- 이용인 신청서 작성, 수정, 삭제
- `2026-001` 형태의 접수번호 자동 생성
- 생년월일 입력 시 연령 자동 계산
- 인테이크 면접지 작성 및 면접자 선택
- 예비이용일지 작성
- 사정보고서 작성
- 대상자별 PDF 파일명 등록 및 통합조회
- 기관 종사자 목록 관리

주의: 현재 저장소의 앱은 `localStorage`를 사용합니다. 즉, 입력 데이터는 테스트 중인 브라우저에만 저장됩니다. 실제 기관 운영에서 여러 담당자가 같은 Google Sheet를 공유해야 한다면 Google Apps Script 저장 함수 또는 별도 백엔드 API 연결이 필요합니다.

## 2. 로컬에서 실행하는 방법

### 2.1 필수 준비물

- Node.js 20 이상 권장
- npm
- 이 저장소 코드

### 2.2 설치 및 실행

터미널에서 저장소 루트로 이동한 뒤 아래 명령을 실행합니다.

```bash
npm install
npm run dev
```

개발 서버가 실행되면 브라우저에서 아래 주소를 엽니다.

```text
http://localhost:3000/
```

### 2.3 빌드 확인

배포 전에 아래 명령으로 타입 오류와 빌드 오류를 확인합니다.

```bash
npm run lint
npm run build
```

## 3. 현장 테스트 절차

### 3.1 이용인 신청서 테스트

1. 왼쪽 메뉴에서 `이용인 신청서`를 클릭합니다.
2. 접수번호가 자동으로 `2026-001` 형태로 표시되는지 확인합니다.
3. 이용인명, 생년월일, 연락처를 입력합니다.
4. 생년월일 입력 후 연령이 자동 계산되는지 확인합니다.
5. 주소칸이 다른 전체 폭 입력칸보다 짧게 표시되는지 확인합니다.
6. `저장`을 클릭합니다.
7. 오른쪽 신청서 선택 목록에 저장한 이용인이 표시되는지 확인합니다.
8. 저장된 이용인을 선택한 뒤 `삭제` 버튼으로 삭제가 가능한지 확인합니다.

### 3.2 인테이크 면접지 테스트

1. 먼저 이용인 신청서를 1건 저장합니다.
2. `기관설정`에서 면접자를 줄바꿈으로 입력하고 저장합니다.
3. `인테이크 면접지` 메뉴로 이동합니다.
4. 대상자를 선택합니다.
5. 이용인명, 나이, 연락처 등 신청서의 중복 정보가 자동으로 불러와지는지 확인합니다.
6. 면접자 드롭다운에 기관설정에서 저장한 종사자가 표시되는지 확인합니다.
7. 면접 내용을 입력하고 저장합니다.

### 3.3 예비이용일지 테스트

1. `예비이용일지` 메뉴로 이동합니다.
2. 대상자를 선택합니다.
3. 기본정보가 자동 반영되는지 확인합니다.
4. `예비이용기간`과 `기록 날짜`가 별도 항목으로 입력되는지 확인합니다.
5. 활동 내용, 지원 내용, 다음 계획을 입력하고 저장합니다.

### 3.4 사정보고서 테스트

1. 먼저 인테이크 면접지를 저장합니다.
2. `사정보고서` 메뉴로 이동합니다.
3. 같은 대상자를 선택합니다.
4. 인테이크 면접지의 욕구, 일상지원, 특이사항이 자동 삽입되는지 확인합니다.
5. 자동 삽입된 내용에 추가로 문장을 입력해도 저장 오류가 나지 않는지 확인합니다.

### 3.5 PDF 보관함 및 통합조회 테스트

1. `통합조회/PDF` 메뉴로 이동합니다.
2. 대상자를 선택합니다.
3. 문서 분류를 입력합니다. 예: `개인정보동의서`, `예비이용기간 확인서`, `복지카드 사본`
4. PDF 파일을 선택해 업로드합니다.
5. 통합조회 표에서 PDF 개수가 아니라 실제 파일명이 표시되는지 확인합니다.
6. 검색창에 이용인 이름 또는 PDF 파일명 일부를 입력해 검색되는지 확인합니다.

권장 파일명 예시는 다음과 같습니다.

- `홍길동_개인정보동의서.pdf`
- `홍길동_예비이용기간확인서.pdf`
- `홍길동_복지카드사본.pdf`
- `홍길동_초기상담기록.pdf`

## 4. 실제 운영 전에 반드시 알아야 할 점

### 4.1 현재 localStorage 방식의 한계

현재 구현은 빠른 테스트와 화면 검증을 위한 프론트엔드 저장 방식입니다.

- 같은 PC와 같은 브라우저에서만 데이터가 보입니다.
- 브라우저 캐시/사이트 데이터 삭제 시 자료가 사라질 수 있습니다.
- 여러 직원이 동시에 같은 자료를 공유할 수 없습니다.
- 민감한 개인정보를 장기 보관하기에 적합하지 않습니다.

따라서 실제 운영에서는 Google Sheets 또는 서버 데이터베이스에 저장하도록 연결해야 합니다.

### 4.2 Google Sheets에 실제 저장하려면 필요한 작업

Google Apps Script 프로젝트에 다음 기능이 필요합니다.

1. 신청서 저장 함수
2. 신청서 삭제 함수
3. 인테이크 저장 함수
4. 예비이용일지 저장 함수
5. 사정보고서 저장 함수
6. PDF 파일 업로드 또는 Drive 저장 함수
7. 기관설정/종사자 저장 함수
8. 통합조회 함수

프론트엔드에서는 현재 `WaitingListService`의 `localStorage` 호출 부분을 `google.script.run` 또는 REST API 호출로 교체해야 합니다.

## 5. Google Apps Script에 붙이는 기본 구조 예시

아래는 실제 운영용으로 바꿀 때의 방향 예시입니다. 현재 저장소에 바로 실행되는 코드는 아니며, Apps Script 편집기에 맞게 적용해야 합니다.

```javascript
const SPREADSHEET_ID = '실제_스프레드시트_ID';

function getSheet_(name) {
  const sheet = SpreadsheetApp.openById(SPREADSHEET_ID).getSheetByName(name);
  if (!sheet) throw new Error('시트를 찾을 수 없습니다: ' + name);
  return sheet;
}

function saveApplicant(data) {
  const lock = LockService.getScriptLock();
  lock.waitLock(10000);
  try {
    const sheet = getSheet_('이용인신청서');
    const receiptNo = data.receiptNo || createReceiptNo_(sheet);
    sheet.appendRow([
      new Date(),
      receiptNo,
      data.name,
      data.birthDate,
      data.age,
      data.gender,
      "'" + data.phone,
      data.guardianName,
      "'" + data.guardianPhone,
      data.address,
      data.serviceType,
      data.requestMemo,
      data.status || '대기'
    ]);
    return { ok: true, receiptNo };
  } finally {
    lock.releaseLock();
  }
}
```

## 6. 개인정보 보호 운영 권장사항

실제 운영 전에 아래 사항을 반드시 확인하세요.

- Google Sheet 공유 권한은 담당자 최소 인원으로 제한합니다.
- 퇴사자 또는 업무 변경자의 접근 권한은 즉시 제거합니다.
- PDF 원본은 Google Drive의 제한된 폴더에 저장합니다.
- 파일명에는 주민등록번호, 상세 질병명 등 과도한 민감정보를 넣지 않습니다.
- 테스트 데이터와 실제 개인정보 데이터를 같은 시트에 섞지 않습니다.
- 월 1회 이상 백업과 접근 권한 점검을 진행합니다.

## 7. 배포 방법 선택지

### 7.1 내부 테스트용

```bash
npm run dev
```

담당자 PC에서 화면과 흐름을 검증할 때 사용합니다.

### 7.2 정적 웹 배포용

```bash
npm run build
```

생성된 `dist/` 폴더를 기관 웹서버, Netlify, Vercel, Firebase Hosting 등에 배포할 수 있습니다. 단, 이 경우도 실제 공동 운영을 위해서는 Google Sheets/API 저장 연결이 필요합니다.

### 7.3 Google Apps Script HTML Service 이식

React 빌드 결과를 Apps Script HTML 파일로 이식하는 방식입니다. 이 방식은 추가 설정이 필요하므로, 운영 전에는 먼저 Google Sheet 저장 함수와 권한 정책을 확정하는 것을 권장합니다.

## 8. 권장 도입 순서

1. 로컬에서 `npm install`, `npm run dev`로 화면을 확인합니다.
2. 테스트 신청자 2~3명을 입력해 업무 흐름을 검증합니다.
3. 기관 종사자 목록과 실제 입력 항목명을 확정합니다.
4. Google Sheets의 탭 구조를 정합니다.
5. `WaitingListService`를 Google Apps Script 저장 API 방식으로 교체합니다.
6. 권한, 백업, PDF 저장 위치를 확정합니다.
7. 실제 담당자 1~2명으로 파일럿 운영합니다.
8. 오류가 없을 때 전체 운영으로 전환합니다.
